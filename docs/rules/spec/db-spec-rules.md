# DB 仕様書規約

## 概要

- 配置場所: `docs/db/` にテーブル単位で管理する
- スキーマ（`backend/src/db/schema/`）を変更したら対応する仕様書も合わせて更新する

---

## ファイル命名・ID体系

| 要素 | 形式 | 例 |
|---|---|---|
| ファイル名 | `DB-{リソース}-{連番2桁}.md` | `DB-USER-01.md` |
| テーブルID | `DB-{リソース}-{連番2桁}` | `DB-USER-01` |
| リソース区分 | `USER` / `AUTH` / `MASTER` | - |

---

## 必須セクション

各 DB 仕様書に以下のセクションを必ず設ける。

| # | セクション | 内容 |
|---|---|---|
| 1 | タイトル（H1） | テーブル名（英語・snake_case） |
| 2 | テーブルID | `DB-XXX-YY` 形式 |
| 3 | テーブル定義 | カラム定義テーブル |
| 4 | 外部キー | 外部キーがある場合のみ記載 |
| 5 | インデックス | PK 以外にインデックスがある場合のみ記載 |
| 6 | 備考 | 特記事項（保存形式・制約・運用ルール等） |

---

## テーブル定義

以下の列でカラムを定義する。

| カラム名（snake_case） | 型 | 必須 | 一意 | デフォルト | 説明 |
|---|---|---|---|---|---|
| id | uuid | ✓ | ✓ | auto | PK |
| created_at | timestamp | ✓ | - | now() | 作成日時 |
| updated_at | timestamp | ✓ | - | now() | 更新日時 |
| deleted_at | timestamp | - | - | - | 削除日時（論理削除） |

- 必須・一意は `✓` / `-` で表記する
- FK の説明欄に `FK → {参照テーブル}.{参照カラム}` と記載する

### 型の選択肢

| 型 | 用途 |
|---|---|
| `uuid` | UUID（PK・FK） |
| `varchar(N)` | 最大 N 文字の文字列 |
| `text` | 文字数制限なしの文字列 |
| `integer` | 整数 |
| `boolean` | 真偽値 |
| `date` | 日付（時刻なし） |
| `timestamp` | 日時（タイムゾーンなし） |
| `decimal(M,N)` | 小数（M桁・小数N桁） |
| `{name} enum` | PostgreSQL Enum 型（→ 対応するDB-MASTER-XX を参照） |

---

## 外部キー

| カラム名 | 参照テーブル | 参照カラム | 削除時の動作 |
|---|---|---|---|
| user_id | users | id | cascade |

削除時の動作の選択肢:

| 値 | 動作 |
|---|---|
| `cascade` | 親レコード削除時に連動して削除する |
| `restrict` | 子レコードが存在する場合は親を削除できない |
| `set null` | 親レコード削除時に FK を NULL にする |

---

## インデックス

PK は記載不要。検索・JOIN で使うカラムや一意制約のみ記載する。

| カラム名 | 種別 |
|---|---|
| email | unique |
| user_id | index |

---

## 命名規約

| 対象 | 規約 | 例 |
|---|---|---|
| テーブル名 | snake_case・複数形 | `user_profiles` |
| カラム名 | snake_case | `birth_date` |
| TypeScript 変数 | camelCase（Drizzle が自動変換） | `birthDate` |

---

## 論理削除

- 削除は物理削除しない。`deleted_at` カラムで論理削除する
- クエリでは `isNull(table.deletedAt)` を WHERE に付けて削除済みを除外する
- 退会済みユーザーの参照については仕様書の備考に明記する

---

## 更新ルール

- テーブルを追加・変更したら以下を同時に更新する
  1. `docs/db/_table_list.md`（テーブル一覧への追記）
  2. `backend/src/db/schema/`（Drizzle スキーマ定義）
  3. マイグレーションファイル（`npm run db:generate` で生成）
- スキーマ定義とマイグレーションファイルは同一コミットに含める
- 新規テーブルを追加するときは `docs/db/_template.md` をコピーして作成する

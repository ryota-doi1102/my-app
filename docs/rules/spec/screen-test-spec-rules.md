# 画面テスト仕様書規約

> テストケース一覧の書き方・共通ルールは `docs/rules/testing/testing-common-rules.md` を参照。
> テストコードの実装規約は `docs/rules/testing/frontend-unit-test-rules.md` を参照。

## 概要

- 配置場所: `docs/tests/frontend/` に画面単位で管理する
- 仕様書とテストコード（`frontend/src/tests/`）は常に同期を保つこと

---

## ファイル命名・ID体系

| 要素 | 形式 | 例 |
|---|---|---|
| ファイル名 | `FE-{リソース}-{連番2桁}.md` | `FE-USER-02.md` |
| テスト ID | `FE-{リソース}-{連番2桁}` | `FE-USER-02` |
| リソース区分 | `USER` / `AUTH` | - |

同一スキーマを共有する複数画面（作成・編集など）は別々のファイルを作成し、差分のみを明記する。

---

## 必須セクション

| # | セクション | 内容 |
|---|---|---|
| 1 | タイトル | `# テスト仕様書 - {FE-ID} {画面名}` |
| 2 | 対象 | ID / 画面名 / パス / スキーマ / フック / テストコードパスの表 |
| 3 | 差分（任意） | 同一スキーマ基準仕様書との差分のみ（独立した仕様書の場合は省略） |
| 4 | テストケース一覧 | TC 番号体系のセクションごとにテーブルを設ける |

---

## TC 番号体系

| 範囲 | 区分 |
|---|---|
| 001〜099 | 必須チェック（フィールドの省略・空文字・null） |
| 100〜499 | 形式・制約チェック（形式・文字数・禁止文字・ビジネスルール等） |
| 500〜599 | 正常系バリエーション（バリデーションを通過するパターン） |
| 600〜699 | API 変換（フォームデータ → API パラメータ変換） |
| 700〜799 | API エラー処理（エラー時の状態・メッセージ） |

---

## 各セクションの記載ルール

### 必須チェック（001〜099）

必須フィールドに対して「省略」「空文字」「null」の 3 パターンを記載する。

フィールドごとに `####` サブセクションを設けてテーブルをまとめる。

```markdown
#### name（氏名）

| テストケースID | テスト内容 | 期待するテスト結果 |
|---|---|---|
| TC-001 | `name` を省略する | invalid / 氏名は必須項目です |
| TC-002 | `name` に空文字 `""` を指定する | invalid / 氏名は必須項目です |
| TC-003 | `name` に `null` を指定する | invalid（型エラー） |
```

### 形式・制約チェック（100〜499）

フォーマット・文字数・許可値などの制約を確認する。フィールドごとにサブセクションを設ける。

```markdown
#### birthDate（生年月日）

| テストケースID | テスト内容 | 期待するテスト結果 |
|---|---|---|
| TC-101 | `birthDate` に YYYY-MM-DD 以外の形式を指定する | invalid / 生年月日はYYYY-MM-DD形式で入力してください |
| TC-102 | `birthDate` に 18 歳未満の日付を指定する | invalid / 18歳未満の方は登録できません |
```

### 正常系バリエーション（500〜599）

バリデーションを通過するパターンを確認する。

| TC | テスト内容 | 期待するテスト結果 |
|---|---|---|
| TC-501 | 必須項目のみを含む最小有効なデータを指定する | valid |
| TC-502 | すべての項目（任意項目含む）を含む完全なデータを指定する | valid |
| TC-5XX | 任意フィールドを省略すると valid になる | valid |
| TC-5XX | 任意フィールドに空文字を指定すると valid になる | valid |

### API 変換（600〜699）

フックの `onSubmit` が API に渡す引数を確認する。

| TC | テスト内容 | 期待するテスト結果 |
|---|---|---|
| TC-601 | 必須項目を入力して送信する | `xxxApi()` が正しい引数で呼ばれる |
| TC-6XX | 任意項目を空文字で送信する | 任意フィールドが `null` で API に渡る |
| TC-6XX | `profileImage` が `File` の場合、base64 に変換されて送信される | `profileImage` が base64 文字列になる |
| TC-6XX | 送信成功後に遷移する | `navigate("○○")` が正しい引数で呼ばれる |

### API エラー処理（700〜799）

API がエラーを返した場合のフックの挙動を確認する。

| TC | テスト内容 | 期待するテスト結果 |
|---|---|---|
| TC-701 | API がエラーを返す | `apiError` にエラーメッセージが設定される |
| TC-7XX | 409 エラー時 | `apiError` が期待値と一致する |
| TC-7XX | API エラー後 | `isSubmitting` が `false` に戻る |

---

## 期待するテスト結果の書き方

| 状況 | 書き方 |
|---|---|
| バリデーション成功 | `valid` |
| バリデーション失敗 | `invalid / {エラーメッセージ}` |
| 型エラー（null 等） | `invalid（型エラー）` |
| API 呼び出し確認 | `{関数名}() が正しい引数で呼ばれる` |
| ページ遷移確認 | `navigate("○○") が呼ばれる` |

---

## 更新ルール

- TC を追加・変更したらテストコードも同時に更新する
- テストコードを変更したら仕様書も同時に更新する
- `docs/tests/frontend/_test_list.md` に追記する
- 新規作成時は `docs/tests/frontend/_template.md` をコピーして作成する

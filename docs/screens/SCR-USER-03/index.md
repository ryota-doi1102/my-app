# ユーザー詳細・編集画面

ユーザーのプロフィール詳細表示と編集を同一画面で行う。表示モード（`view`）と編集モード（`edit`）をトグルで切り替える。

## 基本情報

| 項目 | 内容 |
|---|---|
| ID | SCR-USER-03 |
| パス | /users/:id |
| 認証 | JWT必須 |
| 概要 | ユーザーのプロフィール詳細表示と編集を同一画面で行う画面 |

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.tsx` | ページコンポーネント（UI） |
| `useUserProfile.ts` | 表示・編集モード管理・フォームロジック |

## 機能一覧

| ID | 機能名 | 機能概要 |
|---|---|---|
| F-01 | プロフィール表示 | ユーザーのプロフィール情報を読み取り専用で表示する（view モード） |
| F-02 | プロフィール編集 | フォームでプロフィール情報を入力・バリデーション・更新する（edit モード） |
| F-03 | 年齢の自動計算 | 生年月日の入力をトリガーに満年齢を即時計算して表示する |
| F-04 | 離脱確認ダイアログ | 編集中に変更がある場合、キャンセル時に確認ダイアログを表示する |

### F-01 プロフィール表示

#### モード切り替え

| 状態 | 説明 |
|---|---|
| `view` | プロフィール詳細を読み取り専用で表示 |
| `edit` | プロフィール編集フォームを表示 |

- 初期表示は `view` モード
- 「編集」ボタン押下で `edit` モードへ遷移し、フォームを現在の値でリセットする
- 更新成功時・キャンセル確定時に `view` モードへ戻る

#### レイアウト

1. **プロフィールヘッダー**: アバター画像（なければデフォルトアイコン） + 氏名 + メールアドレス
2. **基本情報セクション**: 生年月日・年齢・性別
3. **連絡先情報セクション**: 電話番号・メールアドレス
4. **住所セクション**: 郵便番号・都道府県・市区町村・番地・建物名
5. **職業情報セクション**: 希望勤務形態（バッジ）・資格（バッジ）・職歴（カード）
6. **自己PRセクション**: テキスト表示
7. **操作ボタン**: 「戻る」（← `/users/list`）・「編集」

#### 表示ルール

- 値が未設定の項目は `—` を表示する
- 希望勤務形態・資格はバッジ形式で並べて表示する
- 職歴は在職期間（`YYYY年M月 〜 YYYY年M月` / 現職の場合は `現在`）と役職をカード形式で表示する

#### 選択肢の取得元

性別・希望勤務形態の選択肢は API から取得せず、`shared/schemas/user.ts` に定義された定数を直接 import して使用する。

| フィールド | import 元 | 値 |
|---|---|---|
| 性別 | `z.enum(['男性', '女性', 'その他'])` の enum 値 | 男性 / 女性 / その他 |
| 希望勤務形態 | `WORK_TYPES` | フルタイム / パートタイム / リモート / フリーランス |

```ts
import { WORK_TYPES } from '@shared/schemas/user'
// gender の選択肢は ['男性', '女性', 'その他'] をリテラルで使用
```

> enum 値は DB スキーマ（`DB-MASTER-01` / `DB-MASTER-02`）と `shared/schemas/user.ts` で同一の値を管理している。選択肢を変更する場合は両方を合わせて修正すること。

#### ボタン

| ボタン | 動作 |
|---|---|
| キャンセル | 変更がなければ即座に view モードへ戻る。変更がある場合は離脱確認ダイアログを表示する |
| 更新 | バリデーション後、更新処理を実行する。成功時は view モードへ戻る |

#### 更新処理フロー

1. 更新ボタン押下時にバリデーションを実行する
2. バリデーションエラーがある場合はエラーメッセージを各フィールドに表示し、処理を中断する
3. バリデーション通過後、フォーム値を API ペイロードへ変換して送信する（下記「任意項目のフィールド送信ルール」参照）
4. リクエスト中は **全フィールドおよび全ボタンを disabled 状態** にして操作を不可とする
5. 更新完了後、`view` モードへ戻る
6. 更新失敗時はエラーメッセージをページ上部に表示し、disabled を解除して再入力を促す

#### 任意項目のフィールド送信ルール

バリデーション通過後、API ペイロードを構築する際に以下のルールでフォーム値を変換する。

| フォーム値 | API ペイロード | バックエンドの動作 |
|---|---|---|
| 文字列（1文字以上） | そのまま文字列を送信 | フィールドを更新する |
| `""` （空文字） または `undefined` | `null` に変換して送信 | フィールドを空に更新する |

**null クリアに対応するフィールド**

| フィールド | 空文字時の送信値 |
|---|---|
| 電話番号 | `null` |
| 郵便番号 | `null` |
| 都道府県 | `null` |
| 市区町村 | `null` |
| 番地 | `null` |
| 建物名・部屋番号 | `null` |
| 自己PR | `null` |

**プロフィール画像の送信ルール**

| フォーム値 | API ペイロード | バックエンドの動作 |
|---|---|---|
| 新規 `File`（ファイル選択あり） | base64 文字列として送信 | 新しい画像を保存する |
| `undefined`（未変更・編集モード初期状態） | 省略 | 既存の画像を保持する |
| `null`（削除ボタン押下後） | `null` として送信 | 既存の画像を削除する |

> 削除ボタンは既存画像がある場合、または新規ファイルを選択した場合に表示される。押下すると `null` がセットされ、保存時に既存画像が削除される。

> 必須項目（氏名・生年月日・性別・メールアドレス・職歴）は常に値を送信する。  
> 希望勤務形態・資格は配列型のため、`null` または空配列 `[]` を送信することで全削除となる。

### F-03 年齢の自動計算

- 生年月日が入力されると即時に年齢を計算して表示する
- 今日の日付を基準に満年齢を算出する
- 生年月日が未入力の場合は空欄とする
- 年齢フィールドはテキスト表示のみで編集不可

---

### F-04 離脱確認ダイアログ

編集モードでフォームに変更がある状態で「キャンセル」を押すと表示する。

| ボタン | 動作 |
|---|---|
| 変更を破棄 | フォームをリセットして `view` モードへ戻る |
| 編集を続ける | ダイアログを閉じて編集を継続する |

> **注意**: ブラウザの戻るボタン・リロード・タブ閉じ等のブラウザネイティブ操作には確認ダイアログを表示しない（`beforeunload` 等は使用しない）

## 状態管理

| 状態 | 型 | 説明 |

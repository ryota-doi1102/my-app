## バリデーション

### ファイルレベル

- ファイルサイズが 5MB 以下であること
- データ行数が 500 件以下であること（ヘッダー行を除く）
- ヘッダー行が上記のカラム構成と完全に一致すること（順番・カラム名）
- データ行が 1 行以上あること
- ファイル内で ID が重複していないこと
- ファイル内でメールアドレスが重複していないこと

### 行レベル

新規登録行（ID 空欄）と更新行（ID 入力あり）でルールが一部異なる。

| フィールド | 新規登録 | 更新 |
|---|---|---|
| ID | — | DB に存在する UUID であること |
| 氏名 | 必須・100 文字以下 | 必須・100 文字以下 |
| メールアドレス | 必須・メールアドレス形式・DB 未登録 | 必須・メールアドレス形式・他ユーザーが使用中でないこと |
| パスワード | 必須・8 文字以上・大文字 1 文字以上・小文字 1 文字以上・数字 1 文字以上 | 無視（バリデーション対象外） |
| 電話番号 | 入力する場合：10〜11 桁の半角数字・ハイフン不可 | 同左 |
| 生年月日 | 必須・YYYY-MM-DD 形式・18 歳以上 60 歳未満 | 同左 |
| 性別 | 必須・`男性` / `女性` / `その他` のいずれか | 同左 |
| 郵便番号 | 入力する場合：7 桁の半角数字・ハイフン不可 | 同左 |
| 希望勤務形態 | 入力する場合：各値が `フルタイム` / `パートタイム` / `リモート` / `フリーランス` のいずれか | 同左 |
| 資格 | 入力する場合：各値が 1 文字以上 | 同左 |
| 職歴1_会社名 | 必須・255 文字以下 | 同左 |
| 職歴1_開始月 | 必須・YYYY-MM 形式 | 同左 |
| 職歴1_終了月 | 入力する場合：YYYY-MM 形式 | 同左 |
| 職歴1_役職 | 必須・255 文字以下 | 同左 |
| 職歴2〜3 | 会社名を入力した場合、同番号の開始月・役職も必須。各フィールドの形式は職歴1 と同じ | 同左 |

**エラーがある場合は全件インポートを中断し、エラー一覧をダイアログで表示する。**

## エラー表示形式

| エラー種別 | 表示例 |
|---|---|
| サイズ超過 | `ファイルサイズが上限（5MB）を超えています` |
| 行数超過 | `データ行数が上限（500 件）を超えています` |
| ヘッダー不一致 | `ヘッダーが仕様と一致しません` |
| ID 不一致 | `2 行目: ID "xxxxxxxx-xxxx-..." に一致するユーザーが見つかりません` |
| ID ファイル内重複 | `3 行目・7 行目: ID "xxxxxxxx-xxxx-..." が重複しています` |
| 必須項目未入力 | `4 行目: 氏名 は必須項目です` |
| 形式エラー | `5 行目: 生年月日 の形式が正しくありません（YYYY-MM-DD で入力してください）` |
| 条件付き必須違反 | `6 行目: 職歴2_会社名 を入力した場合、職歴2_開始月 は必須です` |
| メールアドレス ファイル内重複 | `7 行目・9 行目: メールアドレス test@example.com が重複しています` |
| メールアドレス DB 重複 | `8 行目: メールアドレス yamada@example.com は既に登録されています` |

## 処理フロー

1. CSV ファイルを読み込み、UTF-8 として解釈する
2. ファイルサイズ（5MB 以下）・データ行数（500 件以下）を検証する。超過している場合は処理を中断してエラーを表示する
3. ヘッダー行を検証する。不一致の場合は処理を中断してエラーを表示する
4. 各行の ID 欄を確認し、新規登録（空欄）と更新（入力あり）に分類する
5. 全データ行に対してバリデーションを実行する（新規・更新それぞれのルールで）
6. エラーがある場合は中断し、エラー一覧をダイアログで表示する
7. `CompressionStream`（gzip）で CSV データを圧縮する
8. `POST /api/v1/users/import` に gzip 圧縮済みデータを送信する（`Content-Encoding: gzip`）
9. サーバー側で gzip を解凍し、新規登録・更新を一括処理する
10. インポート完了後、スナックバーで処理件数（例: 新規 3 件・更新 2 件）を表示し、一覧を再取得する

## ブラウザ・インフラ上の制約

### ブラウザ

| 項目 | 内容 |
|---|---|
| `CompressionStream` の対応バージョン | Chrome 80・Firefox 113・Safari 16.4 以降 |
| 非対応ブラウザの扱い | `CompressionStream` が利用不可の場合は圧縮せずにそのまま送信する（フォールバック） |
| ファイルサイズの実用限界 | `File` API はブラウザ固有の上限はないが、利用可能なメモリに依存する。5MB 未満であれば問題なし |

### インフラ

| レイヤー | デフォルト制限 | 必要な対応 |
|---|---|---|
| Nginx（リバースプロキシ） | `client_max_body_size 1m`（デフォルト 1MB） | gzip 圧縮後のサイズ（最大 \~1.5MB 想定）を考慮し、`client_max_body_size 2m;` 以上に設定する |
| Hono（`@hono/node-server`） | デフォルト制限なし | `bodyLimit` ミドルウェアで明示的に上限（例: 2MB）を設定する |
